# AI Ad Layout V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a completed product asset pack into three purpose-aware, editable advertising layout directions that keep product, texture, benefit, copy, and branding visually distinct.

**Architecture:** Keep the existing `LayerData[] → ML_WIZARD_SEED_KEY → Magic Layers editor` contract. Expand the pure composer to build three deterministic layout candidates from semantic assets, then let the intake modal preview/select one candidate before writing the existing seed. The API only reads product/client assets, computes a background-safe text treatment, and never changes product-image-set generation.

**Tech Stack:** Next.js route handlers, TypeScript, Sharp, React, Magic Layers `LayerData`, node built-in test runner.

**Spec:** `docs/AI-LAYOUT-HANDOFF.md`

## Global Constraints

- Work only in `magic-layers` / `adcreation` and the product-page CTA contract; read the product asset pack only.
- Do not change `src/proxy.ts`, inspiration, home, activities creation, or product generation core.
- Preserve `ML_WIZARD_SEED_KEY` shape `{ layers, docW, docH, clientId }` for the final selected candidate.
- New output options must use asset roles `hero`, `detail`, `background`, `benefit`, and `decoration`; old roles remain read-compatible.
- Keep a deterministic layout fallback; do not make an LLM a requirement.
- Do not add a database migration or commit `public/uploads`.
